# Native request revision diagnostic

This fourth-hook probe detects the tested bundle extraction that the
[three-hook diagnostic](../../linux-inventory-hooks.json) missed. It is
research code excluded from the installed framework and SDK. The
[runtime report](../../linux-inventory-request-hooks.json) records the exact
probe hash, calling-convention evidence, counter transitions and cleanup.

The native queued-request function takes one manager pointer. Three Linux
machine-code callers and the complete function extent establish that ABI.
There is no manager declaration in the pinned SDK. The player field at2560
is independently compiled from the actual native Player header and admitted
at runtime only when it points to the expected native manager class.

While that manager has queued work, the probe advances a separate revision
on entry and exit, tracks active depth and forwards the original function.
Empty queues leave the revision unchanged. The existing save, setter and
container-change hooks continue forwarding their original functions.

Vanilla extraction left the bundle slot epoch at4, but advanced the request
revision from6 to8. Restoring the stones returned the entire inventory to its
original saved digest. Another961 idle processing calls left revision10
unchanged. Both watches cleared on disconnect; native saves continued and
the server stopped cleanly. Only the pre-existing items were used.

This provides a tested signal for future lock admission and commit checks.
It does not yet cancel requests, reserve an item, guard partial writes,
recover from a crash or cover every direct server-side component edit.

`build.sh` uses the same private pinned compiler and mount arrangement as the
[earlier probe](../linux-inventory-hooks/README.md). Native Player headers are
compiled only in `layout.cpp`: including them in the executable initially
introduced an unrelated unresolved RakNet constructor. That preflight plugin
was rejected before enable; the corrected probe passed the live test.
The old artifact, world backup and raw receipts remain private. Neither
diagnostic plugin is included in release artifacts.
